# Deviations from the submitted documents

Changes against the SRS, the Software Architecture & Design Specification (SAD) and the
Test Plan. They need to be explained in the final demo.

## Sprint 1

| # | Document | What changed | Why |
|---|---|---|---|
| 1 | Jira plan | SM-43 (per-model failure isolation, Sprint 2) was built in Sprint 1, inside `JobRunner.train_one`. | Without it, one model crashing would fail the whole demo run. |
| 2 | Jira plan | SM-55 (best-overall and best-per-paradigm summary, Sprint 2) was built in Sprint 1 (`evaluator.summarise`). | The Sprint 1 winner banner (SM-57) needs to know the best model. |
| 3 | Jira plan | SM-56 (run metadata) is partly built: dataset, rows, target, task, seed, split fingerprint and column lists. QML subsample size and PCA variance are added with QML in Sprint 2. | The results payload in SRS 3.3 always carries a metadata object. |
| 4 | SRS 2.4 | Python 3.10 works locally as well as 3.11. CI runs on 3.11. | Team laptops have 3.10. |
| 5 | SRS 2.4 | Gunicorn is installed only on Linux. Locally, `python app.py` runs Flask's threaded server. | Gunicorn does not run on Windows. |
| 6 | SRS 3.3 | `/api/status` also returns `models[]`, `log[]`, `elapsed` and `error`. `/api/upload` also returns `name`. `/api/configure` also returns `classes`, `imbalance_ratio`, `trainable` and `reason`. | The Train screen checklist and log (REQ-JB-5) and the blocked-target message (REQ-TG-6) need them. No fields were removed. |
| 7 | SRS UI-7 | An extra frontend module, `dom.js`, holds shared DOM helpers. | Every screen builds elements the same way, using `textContent` only, so file contents cannot inject HTML. |
| 8 | SRS REQ-EV-4 | "Best" means highest accuracy, with F1 as the tie-break. | The SRS does not say which metric decides. |
| 9 | Jira plan | SM-15 and SM-16 moved from Aaditya to Anish, and SM-36 from Anish to Aaditya (Oct 21). | Rebalanced work: Aaditya owns the data path through ML training; Anish owns the API layer. |
| 10 | SRS REQ-EV-1, REQ-JB-5, REQ-RS-3 | Each result also carries `test_time` and `test_rows`. The Train screen shows a "Testing X (i of n)" stage and a `testing` checklist status after each model trains, and the master table has a Test time column. | Models were always scored on the held-out test set, but testing ran inside the "Training" stage and was never shown, so it looked as if models were only trained. |
## Sprint 2

| # | Document | What changed | Why |
|---|---|---|---|
| 11 | SRS CON-4, 2.4 | The quantum classifier runs on PennyLane's `default.qubit` simulator by default. `lightning.qubit` is still installed and is used when `QML_DEVICE=lightning.qubit`. | `default.qubit` simulates a whole mini-batch at once and is about 5x faster for 4 qubits. A default run (2,000 rows, 20 epochs) takes about 57 s on `default.qubit` and about 3.5 min on `lightning.qubit`, so only `default.qubit` meets PERF-4 (1 to 3 minutes). Both are CPU simulators, so CON-4's "simulator only" still holds. |
| 12 | SRS 2.4 | Extra pins: `keras==3.3.3`, `autoray==0.6.12`, `autograd==1.6.2`. | Unpinned, pip installs Keras 3.12, autoray 0.8 and autograd 1.9. PennyLane 0.37 crashes on import with autoray 0.7+ and fails to train with autograd 1.7+. Keras 3.3.3 is the release that matches TensorFlow 2.16.1. |
| 13 | SRS 2.4 (Windows only) | `core/__init__.py` loads PennyLane-Lightning's compiled module before scikit-learn on Windows. | scikit-learn ships an older `msvcp140.dll`. If it loads first, creating a `lightning.qubit` device crashes Python. Linux (Docker, CI, Render) is unaffected. |
| 14 | SRS REQ-TR-5 | The variational circuit is `AngleEmbedding` (RY) followed by 2 `StronglyEntanglingLayers` (24 trainable angles for 4 qubits), trained with Adam (learning rate 0.05, batch 32) on binary cross-entropy. P(class 1) = (1 - <Z0>) / 2, thresholded at 0.5. | The SRS names the stages but not the ansatz or optimiser. |
| 15 | SRS REQ-TR-6 | Only the QML *training* rows are capped at 2,000. The QML model is still tested on the full shared test set. | Testing on the same rows as every other model keeps the comparison fair (BR-2). Prediction is fast; only training is expensive. |
| 16 | SRS REQ-TR-4, REQ-MS-5 | The DNN's validation split is a stratified 20% of the training rows, taken with the run's seed. The default epoch limit is 100 (Advanced panel range 1 to 500). | The SRS does not give the DNN epoch default. Early stopping usually ends training long before the limit. |
| 17 | SRS REQ-JB-6, TBD-5 | Cancelling sets status `cancelled`. The job also stops inside a DNN or QML run, at the next epoch, not only between models. Finished models are kept, and the dashboard opens with those partial results. | Resolves TBD-5. Waiting for a 1-minute QML run to finish before a cancel takes effect felt broken in testing. |
| 18 | SRS REQ-JB-7 | "Session" means a browser, identified by an `HttpOnly` cookie (`pp_session`) set on `/api/train`. A second job from the same browser while one is queued or running gets 409. | The app has no accounts (BR-1), so the cookie is the only way to tell sessions apart. |
| 19 | SRS REQ-JB-3 | Progress also moves *within* the DNN and QML models (one tick per epoch), and the stage label shows the epoch, e.g. "Training Variational Quantum Classifier (8 of 8): epoch 10 of 20, loss 0.647". | These two models take most of the run time, and a bar that froze for a minute looked like a hang. The values are still real server progress. |
| 20 | SRS 3.3 | New endpoints: `GET /api/samples`, `POST /api/samples/<name>`, `POST /api/cancel/<job_id>` and `GET /api/results/<job_id>/csv`. Each result also carries `roc_curve` and `details`, and the results payload carries `status`. | Needed for REQ-UP-9, REQ-JB-6 and REQ-RS-9, and to show each model's epochs, rows and qubits on the dashboard. |
| 21 | SRS REQ-RS-9, UI-7 | CSV export is built on the server (`core/export.py`), not in the browser. | The formula escaping is then enforced on the server and covered by pytest (TC-12). |
| 22 | SRS REQ-RS-6 | The confusion-matrix heatmaps are HTML tables shaded by the row share, not Chart.js charts. | Chart.js has no heatmap type without a plugin, and a table can be read by screen readers. |
| 23 | SRS SEC-5 | In production (`APP_ENV=production`), a job that fails for an unexpected reason shows a generic message. Data problems (for example "no usable feature columns") are still shown in full. | A generic message for a bad dataset would not tell the user what to fix (UI-6). |
| 24 | SRS SEC-7 | Upload cleanup runs before every upload and every 10 minutes in a background thread. Uploads older than `UPLOAD_TTL_SECONDS` (default 1 hour) are deleted, then the oldest files until the folder is under `UPLOAD_DIR_MAX_MB` (default 500). | The SRS does not give a size cap. |
| 25 | SRS SEC-3, COM-3 | In development, CORS also allows `http://localhost` and `http://127.0.0.1` on any port. Production allows only `CORS_ORIGINS`, and no cross-origin access at all when it is empty. | The UI is served from the same origin, so production needs no CORS unless a separate frontend is added. |
| 26 | Test plan | Sprint 2 adds `tests/test_dnn.py`, `test_qml.py`, `test_jobs.py`, `test_export.py` and `test_security.py`. Only the full default QML run is marked `slow`. The other QML tests use 1 epoch and 2 qubits, so CI still exercises QML. | Fast QML tests catch a broken QML pipeline in CI without making the run slow. |
| 27 | SRS PERF-7, TBD-2 | Response-time targets are now defined and measured; see `docs/performance.md`. | Resolves TBD-2 (SM-68). |
| 28 | SRS 2.1, ASM-4, UI-2 | The UI uses the team's chosen "Herbarium" design: graph-paper background, card-stock panels, Instrument Serif, Libre Franklin and IBM Plex Mono. The fonts load from Google Fonts, a second CDN next to Chart.js; Georgia, system-ui and Consolas stand in if it is unreachable. Paradigm colours stay #4c72b0 / #c94f6d / #8172b3, but badges show them as a coloured stripe and border with ink text instead of white text on a filled colour. | Herbarium was picked from five design concepts. White on the DL and QML colours is only 4.35:1 and 4.21:1, below WCAG AA's 4.5:1 for small text; ink on card stock is 11.9:1. |
| 29 | SRS REQ-TR-3, 2.4 | Optional NVIDIA GPU support. With `COMPUTE_DEVICE=auto` (the default), XGBoost trains with `device="cuda"` when the CUDA driver reports a GPU, and the DNN uses any GPU TensorFlow can see (Linux or WSL2 with `requirements-gpu.txt` in place of `tensorflow-cpu`). Every model's details show the device it trained on. The Docker image, CI and Render have no GPU and are unchanged. | Faster training on team laptops with a GPU. The scikit-learn models have no CUDA support, and the QML circuit (2 to 8 qubits) is too small to gain from `lightning.gpu`, so both stay on the CPU. A GPU run can differ slightly from a CPU run with the same seed. |
